# 中国大陆国行 Android 手机系统组件“脱毒”方案

2026-11-20。针对移动终端的系统级反诈、应用扫描与遥测，最彻底的方案是直接使用外版设备（Pixel、外版 iPhone / 三星），或在支持解锁 Bootloader 的机型上刷入 **LineageOS** 等开源类原生系统（或无国行监控组件的官方 Global 国际版固件），从根源上移除整套厂商特权框架。

本仓库针对的是**无法刷机时的退路与止损场景**（例如厂商封锁 BL 解锁、联发科天玑平台缺乏稳定 LineageOS 设备树，或因主力业务暂留原厂 ROM）：整理国行 Android 系统在运营商注册、统计日志、安装扫描与云控更新方面的组件资料，并记录两台实机在原厂固件下的排查与减毒结果。适用范围为国行 Android/AOSP 固件及仍兼容 Android 包管理的华为系统（EMUI、HarmonyOS 2/3/4.x）；HarmonyOS NEXT 等非 Android 固件不在范围内。

原厂固件下的处理顺序遵循：**职责明确的运营商 DM/自注册 → 独立扫描引擎 → 统计与诊断日志 → 与权限、安装及智能功能耦合的组件**。结合系统隐藏设置、ADB 停用/卸载、AppOps 剥权、基于独立 UID 的网络阻断与关键入口开源替换，按单组件逐项操作并保留恢复路径。

实机记录涵盖 realme Neo7（由历史 Android 16 升级至 Android 17 后的状态复核与反诈/埋点子组件拆解）与 moto g100 国行（MYUI 8）。本轮实机新增处理 Neo7 的 DCS（`com.oplus.statistics.rom`）与 Moto 的 Xlog（`com.zui.xlog`）用户级停用，并完成两机全量 UID / 联网权限矩阵梳理。

文档按证据来源分为三档：**实操支持**（有本机或明确机型的实操记录）、**试验候选**（有相近固件或数据库依据，待目标机验证）、**发现项**（已定位包名、权限、服务或调用链，待进一步评估）。每次只处理一个组件，保留原状态并按实际用途回归。

维护检查：`python3 tools/check_publication.py`。该命令检查公开文件边界、本地链接和常见隐私线索，不连接手机或网络；提交前仍须人工审阅。维护范围见 [SPEC](SPEC.md)。
